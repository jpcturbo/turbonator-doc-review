1. Overview & Purpose

BAUDHI defines the accelerated diagnostic communications baud rate used during high-speed serial datalogging and flash transfer operations.

Factory calibrations configure BAUDHI to one count, corresponding to sixty-two thousand five hundred baud (62500 baud). In factory software, when a scan tool requests fast serial data via command eighteen, the engine controller configures the serial hardware using BAUDHI. In Turbonator custom firmware, BAUDHI is also loaded during startup initialization to enable high-throughput PC-based datalogging software to stream real-time sensor values.

2. Operating Conditions (When Does This Take Effect?)

  • Subroutine & Line Numbers: SetupHiSpeedDataTransfer (T-SMEC_v19.asm:3714-3724), instruction line 3720 (ldaa BAUDHI_...). Also line 7236 in ZeroRamFrom0EtoFE.
  • Trigger Protocol:
  • Executed when DRB command 0x12 (enter fast serial mode) is received.
  • Hardware Configuration:
  • Waits for TDRE (transmit data register empty) at line 3719, then writes BAUDHI into CPU_SerialBaudRate at line 3721.

3. Tuner's Guide & Real-World Calibration

  • High-Speed Datalogging Rate:
  • Set to one count (62500 Baud) for maximum data streaming rates with MPScan.
  • Legacy Serial Port Fallback:
  • If using USB-to-serial adapters that drop packets at 62500 Baud, reduce BAUDHI to 9608 Baud (48 counts).
  • Startup Initialization:
  • Loaded during controller cold boot in ZeroRamFrom0EtoFE to establish rapid communication readiness.
  • Factory Default:
  • Configured to 1 count (62500 Baud) across production turbo calibrations.
