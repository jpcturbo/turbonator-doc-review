1. Overview & Purpose

In factory turbocharged Chrysler engine calibrations (such as the 1987 T1/T2 Logic Module), engines run significantly more ignition advance at part throttle (cruising and light load) for sharp throttle response and fuel economy than they do at wide-open throttle (WOT), where elevated cylinder pressures and combustion temperatures demand lower, safer advance to avoid detonation.

When a driver accelerates and begins building boost at part throttle without fully depressing the accelerator pedal to WOT, the ECU needs a method to safely transition ignition timing downward from the higher part-throttle timing table toward the more conservative full-throttle timing table.

ARADVR_AdaptiveRetardAdvanceRatioFromMAP acts as a part-throttle boost retard multiplier / scaling gain. It dictates how aggressively ignition advance is pulled out (retarded) as manifold boost and part-throttle fuel enrichment accumulate.

2. Operating Conditions (When Does This Take Effect?)

This logic is active only when all of the following real-world conditions are met:

  1. Engine is Fully Warmed Up:
    The coolant temperature is above the warm engine switch point (TMPSWP_EngTempSwitchPointForSparkAdvance, typically ~166°F / 74°C). When the engine is cold, cold MAP timing tables (CLDMAP) take precedence.

  2. Part-Throttle Driving (Off-Idle, but Not WOT):
    The driver's foot is on the gas pedal (throttle is open / off-idle), but has not reached Wide-Open Throttle.

    Note: The moment true WOT is triggered, the ECU bypasses this entire transitional calculation and switches directly to the dedicated full-throttle table (WOTMAP_AdvanceFromMAPWarmFull).

  3. Approaching or Building Boost:
    Manifold pressure (MAP) is entering moderate boost—specifically approaching or exceeding the threshold set by OBCONST_OverboostConstant1 (stock value 0xAA, approximately 4.8 to 5.0 psi of boost on a 2-bar MAP sensor)—while the ECU is accumulating Part-Throttle Enrichment (PTE) via Timer_OpenLoopFraction.

3. Tuner's Guide & Real-World Calibration

The result of this calculation is a retard offset that is subtracted from the warm part-throttle MAP advance table (HOTMAP_AdvanceFromMAPWarmPart), with the full-throttle table (WOTMAP_AdvanceFromMAPWarmFull) acting as a hard floor. The final MAP component is then added to the RPM advance curve (GOVNER_AdvanceFromRPM) to produce total ignition timing.

  • Increasing the Value (Larger Number):
  • What it does: Increases the amount of timing pulled out under part-throttle boost.
  • Effect on Total Timing: Retards total ignition timing much faster, pulling total advance down to match the conservative WOT table sooner.

  • Real-World Driving Feel: Produces a more conservative, knock-resistant tune under heavy mid-throttle load (e.g., pulling a grade or towing), though power delivery may feel slightly softer as boost builds.

  • Decreasing the Value (Smaller Number):

  • What it does: Decreases the amount of timing pulled out under part-throttle boost.
  • Effect on Total Timing: Advances total ignition timing during boost transitions, keeping ignition advance closer to the higher part-throttle curve.

  • Real-World Driving Feel: Delivers sharper throttle response and stronger mid-range torque when rolling into boost, but increases the risk of spark knock if your base part-throttle timing table is too aggressive for the fuel octane.

  • Setting the Value to Zero (0x00):

  • What it does: Completely disables this transitional boost-retard mechanism.
  • Effect on Total Timing: The ECU will not pull any progressive timing based on boost at part throttle; it will run the raw part-throttle table until you either floor it to WOT or the table's values naturally dip below the WOT curve.

4. Technical / Assembly Mechanics (Reference)

Inside T-LMv13.asm (lines 6606–6631), the calculation proceeds as follows:

LEFF1:  ldab MapValue
        cmpb OBCONST_OverboostConstant1    ; Compare MAP against boost threshold (0xAA ~ 5 psi)
        bcc  LF002                         ; If MAP >= OBCONST, jump to multiply with A = Timer_OpenLoopFraction
        aba                                ; A = Timer_OpenLoopFraction + MapValue
        bcc  LEFFD
        ldaa #0xff                         ; Clamp sum to 255
LEFFD:  suba OBCONST_OverboostConstant1    ; A = (Timer_OpenLoopFraction + MapValue) - OBCONST
        bls  LF00A                         ; If <= 0, skip multiply (Temp1 stays 0)
LF002:  ldab ARADVR_AdaptiveRetardAdvanceRatioFromMAP ; Load B with ARADVR (stock 0x1F)
        mul                                ; D = A * ARADVR
        adca #0x00                         ; Fixed-point round-up if bit 7 of B is set
        staa Temp1                         ; Store retard amount into Temp1

LF00A:  ldaa MapValue
        ldx  #HOTMAP_AdvanceFromMAPWarmPart
        jsr  Lookup4ByteTable              ; A = HOTMAP(MapValue)
        ldab FACALC_AdaptiveRetardEnable   ; Stock is 0xFF (signed negative / bit 7 set)
        bmi  LF01F                         ; Branches to subtract Temp1
        ...
LF01F:  suba Temp1                         ; A = HOTMAP - Temp1
        cmpa Temp0                         ; Compare against WOTMAP floor (Temp0)
        ble  LF027                         ; If (HOTMAP - Temp1) <= WOTMAP, clamp to WOTMAP
LF025:  staa Temp0                         ; Temp0 = HOTMAP - Temp1
LF027:  ...

Mathematical Summary:

  1. Input Delta ($A$): - If MAP ≥ OBCONST, A = Timer_OpenLoopFraction. - If MAP < OBCONST, A = (Timer_OpenLoopFraction + MAP) - OBCONST. If A ≤ 0, retard is $0$.
  2. Retard Offset:

Temp1 = round((A × ARADVR / 256))

  1. Clamping:

Base MAP Spark = \max(WOTMAP, HOTMAP - Temp1)

5. Calibration Notes & System Dependencies

[!NOTE] Not Knock-Sensor Adaptive Retard:
Despite the historical label ARADVR_AdaptiveRetardAdvanceRatioFromMAP assigned during early disassembly efforts, this routine has absolutely nothing to do with knock-sensor adaptive retard.
Real knock retard (both short-term per-cylinder retard and long-term learned adaptive retard from the knock sensor) is handled by dedicated knock detection routines elsewhere in the code (KnockDetect_MM and HandleKnockRetard). This constant functions purely as a part-throttle-to-full-throttle boost timing blend multiplier.
