1. Overview & Purpose

ENDITM (ECU_ID) is a critical 16-bit calibration identifier placed at the very beginning of the calibration ROM table structure (address $C000, offset $0092).

This 2-byte word represents the engineering calibration release ID (in this stock binary, 0xA171). When a factory Chrysler diagnostic readout box (DRB-II) or modern scan tool queries the ECU over the serial communications interface (SCI), the diagnostic subroutine DRB_SendROMSerial_MM transmits ENDITM to identify the engine displacement, transmission type, model year, and emissions calibration family. Furthermore, the ECU's power-on self-test routine ResetStartup uses ENDITM to verify ROM integrity by calculating an 8-bit additive checksum of the entire calibration table space.

2. Operating Conditions (When Does This Take Effect?)

  • Accessed during system reset in ResetStartup (line 688) and ChecksumLoop (line 694).
  • Queried during serial diagnostic sessions in DRB_SendROMSerial_MM (line 2501).
  • Permanent ROM constant stored at $C000.

3. Tuner's Guide & Real-World Calibration

  • Tuning Usage: When modifying custom calibrations in MPTune, updating or modifying this identifier is typically handled automatically or left intact. Changing this identifier alters what model number displays on scan tools (e.g. Snap-on MT2500 or DRB-II).
  • Checksum Verification: During power-on boot, the ECU adds all calibration bytes and subtracts the second byte of ENDITM (subb ENDITM_ECUID+1). If the calculated sum does not equal zero, the ECU flags a memory checksum fault (ThrowNonCriticalError), storing Fault Code 53 / 8-bit error flag in ErrorBitRegisterStored0.
