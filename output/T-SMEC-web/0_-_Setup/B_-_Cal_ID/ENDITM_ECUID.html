1. Overview & Purpose

ENDITM defines the primary electronic calibration identifier word within the engine controller ROM header.

In production vehicles, this numerical identifier differentiates specific powertrain calibrations across model years, engine displacements, turbocharger packages, and transmission configurations, such as calibration A283 for the nineteen eighty-nine two-point-five-liter turbo automatic. Handheld diagnostic scan tools read ENDITM during the initial communication handshake to automatically identify the vehicle calibration. Crucially, the low-order byte of ENDITM also serves as the expected target value for the internal memory checksum verification algorithm, which verifies calibration ROM integrity during startup.

2. Operating Conditions (When Does This Take Effect?)

  • Subroutine & Line Numbers: CaculateChecksum (T-SMEC_v19.asm:4141-4178), instruction line 4172 (cmpa ENDITM_ECUID+1), and SendECUIDToSCI (T-SMEC_v19.asm:3829-3841).
  • Checksum Comparison:
  • Accumulator A sums all calibration ROM bytes between #ENDIT1_PNPrefix and #0xB600 / #0xB800.
  • Line 4172 executes cmpa ENDITM_ECUID+1.
  • If not equal (bne L1291), the controller loads register D with error code 0x0201 and branches to ThrowNonCriticalError (Error 53).
  • Diagnostic Output:
  • Sent across the serial interface as bytes 2 and 3 of the ECU ID sequence in SendECUIDToSCI.

3. Tuner's Guide & Real-World Calibration

  • Scan Tool Recognition:
  • Factory scan tools query ENDITM to identify vehicle powertrain calibration; altering this word may require manual vehicle selection on legacy diagnostic equipment.
  • Hardware Checksum Target:
  • The low-order byte (ENDITM_ECUID+1, 131 counts in stock A283) is the exact target compared against the calculated memory checksum in CaculateChecksum.
  • Calibration Integrity:
  • Whenever calibration constants or tables are edited, CHKFIX must be adjusted so the total byte sum matches the target byte in ENDITM, preventing error code 53.

5. Calibration Notes & System Dependencies

  • Dual Role: Functions as both the external diagnostic calibration identifier and the internal hardware checksum target.
  • Firmware Anomaly: The comparison instruction specifically references ENDITM_ECUID+1, evaluating only the low byte.
  • Pairing: Directly paired with CHKFIX, which is tuned so the entire ROM sum matches ENDITM_ECUID+1.
